## 1. Startup and login

### 1.1 LLAppViewer: process-level initialisation
`LLAppViewer::init()` (`newview/llappviewer.cpp:860`) runs once: logging (`initLoggingAndGetLastDuration` `:2741`), `initConfiguration()` (`:3003`; settings files, command line), `initThreads()` (`:2575`, see §10), `initWindow()` (`:3712`; creates `gViewerWindow`, GL context, loads UI), `initCache()` (`:5239`; texture cache, disk cache, VOCache). Then `frame()` (`:1527`) loops `doFrame()` (`:1571`) until exit; `cleanup()` (`:2007`) tears down in reverse. Shutdown goes through `requestQuit` → `idleShutdown()` (`:6325`) → `sendLogoutRequest()` (`:6423`; UDP `LogoutRequest`, waits for `LogoutReply` or `gLogoutMaxTime`).

Everything in-world is driven from `doFrame()`; before login the same loop is running and `idle()` (`:5860`) short-circuits into `idle_startup()` while `LLStartUp::getStartupState() < STATE_STARTED` (`:5949-5958`).

### 1.3 Login via XML-RPC
- `LLLoginInstance` (`newview/lllogininstance.cpp`) builds the request in `constructAuthParams` (`:156-260`): `requested_options` = `inventory-root, inventory-skeleton, inventory-lib-root, inventory-lib-owner, inventory-skel-lib, initial-outfit, gestures, display_names, event_categories, event_notifications, classified_categories, adult_compliant, buddy-list, newuser-config, ui-config, advanced-mode, max-agent-groups, map-server-url, voice-config, tutorial_setting, login-flags, global-textures` (+ `god-connect`; OpenSim adds `currency, max_groups, search, destination_guide_url, avatar_picker_url`, `:162-209`). `request_params` = `start` (`"home"`/`"last"`/`uri:...`), `agree_to_tos`, `read_critical`, `last_exec_event`, `last_exec_duration`, `last_exec_session_id`, `mac` (hashed unique id), `version`, `channel`, `platform`, `address_size`, `platform_version`, `platform_string`, `id0` (serial), `host_id`, `extended_errors`, `token`, plus the credential's own params (`first`, `last`, `passwd` as `$1$md5`) and `mfa_hash` (`:213-260`, `:358`, `:595-612`).
- Transport: `LLLogin::Impl::loginCoro` (`viewer_components/login/lllogin.cpp:135`) posts to the `"LLXMLRPCTransaction"` event pump and suspends (`:144`, `:174`); `LLXMLRPCListener` (`newview/llxmlrpclistener.cpp`) runs `LLXMLRPCTransaction` whose `Handler` is an `LLCore::HttpHandler` (`newview/llxmlrpctransaction.cpp:58-75`) — i.e. XML-RPC over llcorehttp, no libxmlrpc. Method is `login_to_simulator`; a response may carry `next_method` for multi-step (TOS/MFA) flows (`lllogin.cpp:195-218`). Progress is published as `LLSD` events `{state: offline|online, change: authenticating|downloading|connect|fail.login|disconnect}` (`:92`, `:165-280`).
- Response handling (`process_login_success_response`, `newview/llstartup.cpp:4780-5270`): `udp_blacklist` → `banUdpMessage` per name (`:4789-4792`, `:4694-4710`); `agent_id` (`:4796`), `session_id` (`:4814`), `secure_session_id` (`:4823`), `display_name/first_name/last_name` (`:4831-4872`), `agent_access_max`/`agent_region_access` (`:4889-4903`), `start_location` (`:4910`), **`circuit_code`** (`:4916`), **`sim_ip`/`sim_port`** → `gFirstSim` (`:4921-4922`), `region_x`/`region_y` → `gFirstSimHandle` (`:4932-4933`), FS `region_size_x/y` (`:4942-4950`), `look_at` (`:4953`), **`seed_capability`** → `gFirstSimSeedCap` (`:4962`), `seconds_since_epoch` (`:4965`), `home` (`:4991`), `message` (MOTD, `:5009`), `inventory-root[0].folder_id` (`:5024`), `login-flags[0]` (`:5031`), `voice-config` (`:5078`), `map-server-url` (`:5085`), `web_profile_url`, `classified_fee`, `directory_fee`, `newuser-config`, `initial-outfit[0]`, **`agent_appearance_service`** (`:5178`), `openid_url/openid_token`, `max-agent-groups`, OpenSim `currency`, `avatar_picker_url`, `destination_guide_url`. Account benefits from `account_type`, `account_level_benefits`, `premium_packages` (`:4727-4744`). Inventory skeleton arrays are consumed later in the inventory states (§8.2).

### 1.4 First region connection
1. `LLWorld::addRegion(handle, host, w, h)` (`newview/llworld.cpp:520`) creates the `LLViewerRegion`, links it to neighbours already known (`:625-666`) and `regionp->setSeedCapability(url)` (`newview/llviewerregion.cpp:3601`) launches `requestBaseCapabilitiesCoro`, which POSTs the LLSD array from `buildCapabilityNames` (`:3462-3594`, 117 names) to the seed URL and stores the returned map via `setCapability` (`:3646`); `EventQueueGet` starts the event poll (§2.5) and `SimulatorFeatures` is fetched (`:2565-2616`).
2. `UseCircuitCode` is a reliable UDP message; the circuit is marked trusted (`enableCircuit(host, true)`); the ack sets `gGotUseCircuitCodeAck` (`llstartup.cpp:2477-2495`).
3. `CompleteAgentMovement {AgentID, SessionID, CircuitCode}` (`newview/llviewermessage.cpp:497-508`).
4. The sim answers with **`RegionHandshake`** (processed in `process_region_handshake` → `LLViewerRegion::unpackRegionHandshake`, `newview/llworld.cpp:1728`, `llviewerregion.cpp:3246`): `RegionFlags`, `SimAccess`, `SimName`, `SimOwner`, `IsEstateManager`, `WaterHeight`, `BillableFactor`, `CacheID` (keys the object cache), `RegionInfo2.RegionID`, `RegionInfo3` (CPU class/ratio, colo, product SKU/name), `RegionInfo4` (`RegionFlagsExtended`, `RegionProtocols`), terrain base/detail textures and start heights/ranges (`:3261-3355`). The viewer replies with `RegionHandshakeReply {Flags}` including `REGION_HANDSHAKE_SUPPORTS_SELF_APPEARANCE` and the VOCache flags (`:3438-3445`); only after this reply does the sim start streaming `ObjectUpdate*`/`LayerData`.
5. **`AgentMovementComplete`** (`process_agent_movement_complete`, `llviewermessage.cpp:3851-3990`): checks agent/session, reads `Data.Position`, `LookAt`, `RegionHandle`, `SimData.ChannelVersion`; sets `gAgent.setRegion(regionp)`, `gObjectList.shiftObjects(shift)` (the agent-relative frame moves), asset/name-cache upstream, `gViewerThrottle.sendToSim()` (`AgentThrottle`), `gViewerWindow->sendShapeToSim()` (`AgentHeightWidth`); if it was a teleport, `TELEPORT_START_ARRIVAL`, FS re-sends legacy `AgentSetAppearance` (`:3987`).
6. From then on `send_agent_update` (`:4187-4330`) sends `AgentUpdate` at most 125/s and at least 1/s (`:4228-4231`) with body/head rotation, `State`, camera center/axes, `Far`, `ControlFlags`, `Flags`; `gAgent.resetControlFlags()` each frame (`llappviewer.cpp:5993`).

Neighbour regions arrive as `EnableSimulator {Handle, IP, Port}` (`process_enable_simulator`, `newview/llworld.cpp:1584-1645`): `enableCircuit(sim, true)`, `addRegion`, and a `UseCircuitCode` to the neighbour; the neighbour's seed cap arrives later over the **event queue** as `EstablishAgentCommunication {agent-id, sim-ip-and-port, seed-capability}` (`LLEstablishAgentCommunication::post`, `:1655-1712`). `EnableSimulator`, `CrossedRegion`, `TeleportFinish` are tagged `UDPBlackListed` in the template (they only arrive via the event queue on SL); `DisableSimulator` (`:1715`) tears a circuit down.


## 2. The message layer

### 2.1 LLMessageSystem and the template
- The wire format is defined by `../scripts/messages/message_template.msg` (`version 2.0`, line 3; 483 message blocks; highest numbers Low 431 / Medium 18 / High 30, lines 9-11). Each message is `{ Name Frequency Number Trust Encoding [UDPDeprecated|UDPBlackListed] { Block Single|Multiple N|Variable { Field Type [size] } ... } }`. Block types `MBT_SINGLE/MULTIPLE/VARIABLE` (`llmessage/llmessagetemplate.h:174-178`); trust `MT_TRUST/MT_NOTRUST` (`:250-251`); the parser handles `UDPDeprecated`/`UDPBlackListed` (`llmessage/llmessagetemplateparser.cpp:523-527`; 17 and 4 messages respectively), and `banUdpMessage` (`llmessage/message.cpp:4022`) is driven by the login response's `udp_blacklist` so blacklisted messages are only accepted via the event queue.
- Field types `MVT_*` (`llmessage/message.h:1000-1097`): fixed-size scalars, `LLUUID`, `IPADDR/IPPORT` (byte-swizzled), `LLVector3/4/3d`, `LLQuaternion` (x,y,z only, w inferred), `Variable 1|2` (1- or 2-byte length prefix), `Fixed N`.
- Message ids on the wire: High = 1 byte, Medium = `0xFF` + 1 byte, Low = `0xFFFF` + 2 bytes, Fixed = `0xFFFFFFxx` (`lltemplatemessagereader.cpp:448-500`; e.g. `num = 0xFFFF0000 | id` at `:488`). The reader does `validateMessage` (`:775`) → `decodeTemplate` → `decodeData` (`:536`) into per-block `LLMsgData`, then `readMessage` (`:811`) calls the registered handler.
- Handler registration: `setHandlerFunc(name, void(*)(LLMessageSystem*, void**), user_data)` stores a single function pointer per template (`llmessage/message.h:383-386`, `llmessagetemplate.h:360-378`); the viewer registers ~150 handlers, mostly in `register_viewer_callbacks` (`newview/llstartup.cpp:3805-3994`), the rest in subsystem `registerCallbacks` (inventory `newview/llinventorymodel.cpp:3902-3933`, avatar tracker, etc.). Handlers read fields with `getU32Fast(_PREHASH_Block, _PREHASH_Field, out, block_index)`; `_PREHASH_*` are interned strings from `llmessage/message_prehash.h`. One handler per message name; no multicast.

### 2.2 Packet layout, zero-coding, reliability, acks
- Packet header (`llmessage/message.h:124-138`): byte 0 flags (`LL_ZERO_CODE_FLAG 0x80`, `LL_RELIABLE_FLAG 0x40`, `LL_RESENT_FLAG 0x20`, `LL_ACK_FLAG 0x10`), bytes 1-4 big-endian packet sequence id (`PHL_PACKET_ID = 1`), byte 5 extra-header length (`PHL_OFFSET = 5`); `LL_PACKET_ID_SIZE = 6` (`llcircuit.h:59`); then the message id and blocks. Max packet `NET_BUFFER_SIZE 0x2000` (`net.h:33`); the sender warns above 1500 bytes except for `ChildAgentUpdate`/`SendXferPacket` (`message.cpp:1176-1184`).
- Zero-coding: runs of zero bytes after the 6-byte header are encoded as `00 count` (count wraps for >255) (`zeroCodeExpand`, `message.cpp:2840-2910`); applied when the template says `Zerocoded` (`compressMessage` in the builder).
- Appended acks: if `LL_ACK_FLAG`, the last byte is the ack count and the preceding `count*4` bytes are packet ids being acknowledged (receive `:546-560`; send appends up to `min(space_left, 250)` acks and sets the flag, `:1233-1270`). Standalone `PacketAck` (Fixed `0xFFFFFFFB`) carries a `Packets Variable {ID U32}` list; `LLCircuit::sendAcks(collect_time)` flushes pending acks after `AckCollectTime` (0.1 s) (`llcircuit.cpp:1110`, `llappviewer.cpp:6714`).
- Reliable send: `sendReliable(host, retries, ping_based, timeout, cb, data)` sets `LL_RELIABLE_FLAG`, `cdp->addReliablePacket` keeps a copy in `mUnackedPackets` (`llcircuit.h:246`), `LLCircuit::resendUnackedPackets` (`llcircuit.cpp:591`) resends with `LL_RESENT_FLAG` after `LL_RELIABLE_TIMEOUT_FACTOR (5) * averaged ping` or the explicit timeout, up to `LL_DEFAULT_RELIABLE_RETRIES (3)`; failure invokes the callback with the "failed" flag (used by `UseCircuitCode`). Duplicate resends are detected via `mRecentlyReceivedReliablePackets` and re-acked (`message.cpp:602-640`).
- Receive loop: `checkMessages` (`message.cpp:491-740`) reads one datagram from `LLPacketRing`, strips acks, un-zero-codes, resolves/creates the circuit (`findCircuit(host, resetPacketId)`), rejects messages from unknown circuits unless `UseCircuitCode`, rejects trusted-template messages from untrusted circuits (`sendDenyTrustedCircuit`), validates and dispatches. Sequence gaps are tracked in `checkPacketInID` (`llcircuit.cpp:658`) to count lost packets (`mPacketsLost`, `mPotentialLostPackets`).
- Circuits (`LLCircuit`/`LLCircuitData`, `llcircuit.h:77-290`): keyed by `LLHost` (ip:port); fields include `mTrusted`, `mbAlive`, `mBlocked`, in/out packet ids with wrap tracking, `mPingDelay`/`mPingDelayAveraged` (alpha 0.2, clamped 100..2000 ms, `:46-48`), `mUnackedPackets`, `mAcks`, `mRemoteID/mLocalEndPointID`. Heartbeat: `StartPingCheck {PingID U8, OldestUnacked U32}` every `circuit_heartbeat_interval` = 5 s with jitter (`llcircuit.cpp:120-122`, `:823-841`); `CompletePingCheck` returns; `checkCircuitTimeout` (`:1065`) declares the circuit dead when no ping for `circuit_timeout` = 100 s (`llstartup.cpp:915-916`); `LLAppViewer::idleNetwork` force-disconnects when the agent region's circuit dies (`llappviewer.cpp:6729-6742`). `mBlocked` is set when `PING_RELEASE_BLOCK` pings are outstanding (`llcircuit.cpp:63`, `:1314`).
- The per-frame network slice: `idleNetwork` (`llappviewer.cpp:6651-6720`) loops `checkAllMessages` up to `MESSAGE_MAX_PER_FRAME` or `CheckMessagesMaxTime`, drains the socket into the packet ring if it falls behind (growing the time budget by 3.5%/frame), then `processAcks` (resend, send acks, watchdog), `gXferManager->retransmitUnackedPackets()`, `gAssetStorage->checkForTimeouts()`, throttle update.

### 2.3 Throttles
`LLThrottleGroup` has seven categories `TC_RESEND, TC_LAND, TC_WIND, TC_CLOUD, TC_TASK, TC_TEXTURE, TC_ASSET` (`llmessage/llthrottle.h:56-65`). The viewer sends its desired per-category bits/s to each sim in `AgentThrottle {Throttle: GenCounter, Throttles Variable(7×F32)}` (`newview/llviewerthrottle.cpp:154`, `sendToSim :240`) from presets keyed by `ThrottleBandwidthKBPS` (`BW_PRESET_50/300/500/1000`, `:73-76`, default 3000 kbps `:250`) and a dynamic adjustment driven by packet loss (`updateDynamicThrottle :310`). These throttles are server-side: they shape what the sim sends (objects, terrain, UDP textures/assets); the viewer only measures.

Event-queue messages are delivered on the main thread from the coroutine, interleaved with UDP processing.

The resulting architecture is a two-transport, main-thread-serialised message bus: UDP packets are decoded in `idleNetwork`, event-queue LLSD is decoded in a fiber resumed in the same frame, and both end up in the same per-name handler function table.

### 3.2 Object update decoding
`LLViewerObjectList::processObjectUpdate(msg, user_data, update_type, compressed)` (`newview/llviewerobjectlist.cpp:446-757`) handles `ObjectUpdate` (`OUT_FULL`), `ObjectUpdateCompressed` (`OUT_FULL_COMPRESSED`), and `ImprovedTerseObjectUpdate` (`OUT_TERSE_IMPROVED`); `ObjectUpdateCached` goes to `processCachedObjectUpdate` (`:766`). Common header `RegionData {RegionHandle U64, TimeDilation U16}`; the region must be known. Per block:
- **Full**: `FullID`, `ID` (local), `PCode`; new objects are created with `createObject(pcode, region, fullid, local_id, sender)` (`:696`) after FS blacklist/friends-only checks (`:682-694`). Cache-eligible full updates (`!FLAGS_TEMPORARY_ON_REZ`) are first stored via `regionp->updateCacheEntry` (`:611`).
- **Compressed**: the `Data` blob is read with an `LLDataPackerBinaryBuffer`; the list head is `ID UUID, LocalID U32, PCode U8` (`:535-538`); non-temporary objects are **not instantiated here**: `regionp->cacheFullUpdate(dp, flags)` stores the blob in the VOCache and `continue`s (`:552-556`) — instantiation happens later from the cache when the entry is visible (§3.3). Terse compressed updates carry only `LocalID` (`:559-572`).
- **Terse**: `ID` local only (`:573-586`); unknown ids are counted in `mNumUnknownUpdates`.
- Then `processUpdateCore` (`:246-335`): `objectp->processUpdateMessage(...)`, `updateActive`, `gPipeline.addObject(objectp)` for new objects, `setPixelAreaAndAngle`, `findOrphans` (children that arrived before their parent are parked in an orphan list keyed by parent local id and re-linked here), and create-selected handling.

`LLViewerObject::processUpdateMessage` (`newview/llviewerobject.cpp:1205-2540`) is the decoder. The `ObjectData` binary blob comes in fixed sizes (`:1219-1226`): 60 (full-precision object: pos, vel, acc, rot as 3 floats, angvel), 76 (avatar: + collision plane vec4), 124/140 (future extended), 32/48 (terse 16-bit: U16-quantised pos/vel/acc/rot/angvel over region size and ±256/±64 ranges), 64/80 (terse extended). Decoding by `length` (`:1395-1475` full, `:1485-1560` terse). The full update additionally reads `CRC` (`mTotalCRC :1356`), `ParentID`, `Sound/OwnerID/Gain/Radius/Flags`, `Material`, `ClickAction`, `Scale` (`:1356-1366`), `UpdateFlags` (`:1452`), `State` (attachment point for avatars/attachments, `:1458`), `NameValue` (`:1465-1470`), `Data` (tree species/particle scratch), `Text`+`TextColor` (hover text, `:1517-1556`), `MediaURL` (`:1560`), `PSBlock` (`unpackParticleSource`, `:1566`), `ExtraParams` (`:1575-1598`: `num_params U8` then `{param_type U16, size U32, data}` via `unpackParameterEntry`), `TextureEntry` (`unpackTEMessage`) and `TextureAnim`; the compressed path reads the equivalent fields from the packer with a `SpecialCode` bitmask (`:1817-1958`) selecting optional sections (angular velocity, parent, tree data, particles, text, media, sound, name-values). The last ~500 lines reconcile parent changes (`mParentID`, `LLViewerObjectList::findOrphans`, attachments → `LLVOAvatar::attachObject`), set dirty bits through `setChanged(MOVED|ROTATED|SCALED|...)` and `gPipeline.markMoved/markRebuild`, and apply `sPingInterpolate` (advance position by half RTT, `:2300`). Dead-reckoning between updates is `idleUpdate` (`:2541`): `interpolateLinearMotion` with `sVelocityInterpolate`, stopping prediction after `sMaxUpdateInterpolationTime` 3 s and tapering after 2 s, and not across region crossings for 1 s (`:126-143`).

Extra-parameter types (`llprimitive/llprimitive.h:111-120`): `PARAMS_FLEXIBLE 0x10, LIGHT 0x20, SCULPT 0x30, LIGHT_IMAGE 0x40, MESH 0x60, EXTENDED_MESH 0x70 (animesh flag), RENDER_MATERIAL 0x80 (GLTF material asset ids per face), REFLECTION_PROBE 0x90`; `unpackParameterEntry` (`llviewerobject.cpp:6734-6802`). `LLVOVolume::processUpdateMessage` (`newview/llvovolume.cpp:355`) layers on `LLVolumeParams` changes (`setVolume :1229`), sculpt texture / mesh id (`updateSculptTexture :1371`, `sculpt :1498`, `notifyMeshLoaded :1453`), light, flexible, and media.

Texture entries: `LLPrimitive::parseTEMessage/unpackTEMessage` (`llprimitive/llprimitive.cpp:1385-1560`) decode the `TextureEntry Variable 2` blob into up to `MAX_TES = 45` faces (`:1217`, buffer `MAX_TE_BUFFER 4096` `:1231`); the format is a sequence of per-attribute arrays (`image_ids[16]`, `colors[4]`, `scale_s/t F32`, `offset_s/t S16`, `image_rot S16`, `bump U8` (bump|shiny|fullbright bits), `media_flags U8`, `glow U8`, `material_data[16]` = `LLMaterialID`) each run-length coded with a face bitmask (`:1219-1229`). An `LLTextureEntry` (`llprimitive/lltextureentry.h`) holds those plus `LLMediaEntry*`, an `LLMaterial` (legacy normal/spec via `RenderMaterials` cap) and `LLGLTFMaterial` + override (`:199-211`). GLTF overrides arrive via `GenericStreamingMessage` → `LLGLTFMaterialList::applyOverrideMessage` (`newview/llgltfmateriallist.cpp:171`) and are edited through the `ModifyMaterialParams` cap (`:388-500`); they are cached in the VOCache "extras" file (§3.3).

`KillObject {ObjectData[]{ID U32}}` → `process_kill_object` (`llviewermessage.cpp:4658`): resolves the local id for the sender, `gObjectList.killObject`, which also kills children, deselects and tells the region cache (`LLViewerRegion::killCacheEntry :1260`).

### 3.3 VOCache: region object cache
- In-memory: `LLViewerRegion` keeps `mCacheMap` (local id → `LLVOCacheEntry`), a `LLVOCachePartition` octree of cache entries (`newview/llvocache.h:216`), `mVisibleEntries`, `mWaitingList` (priority by scene contribution = projected pixel area), `mActiveSet`, `mCacheMissList`. An entry (`llvocache.h:60-140`) stores `mLocalID`, `mCRC`, `mUpdateFlags`, hit/dupe/CRC-change counters, the raw compressed-update blob (`mBuffer`/`mDP`), `mParentID`, children, bounding sphere, and a state machine `INACTIVE → IN_QUEUE → WAITING → ACTIVE` (+ `IN_VO_TREE`) (`:63-73`).
- Flow: `cacheFullUpdate(dp, flags)` (`llviewerregion.cpp:2932`) stores/updates the blob and decodes bounding info into the octree. Every frame `LLWorld::updateRegions` (1 ms budget) → `LLViewerRegion::idleUpdate` (`:1705`) → `killInvisibleObjects`, `updateVisibleEntries` (frustum/occlusion-culls the `LLVOCachePartition` with the world camera, `llvocache.cpp:1039-1093`, `UseObjectCacheOcclusion`), `createVisibleObjects` (`:1588`) which calls `addNewObject(entry)` → `gObjectList.processObjectUpdateFromCache(entry, region)` (`llviewerobjectlist.cpp:337`) for up to `NewObjectCreationThrottle` entries per frame. The viewer therefore instantiates objects **only when their cached bounds are visible**; the server streams compressed updates for everything in the interest list. `ObjectUpdateCached` probes (`probeCache :3071`) compare CRCs: hit → mark valid/record hit, CRC mismatch → `CACHE_MISS_TYPE_CRC`, absent → `CACHE_MISS_TYPE_TOTAL`; misses are batched into `RequestMultipleObjects {CacheMissType U8, ID U32}` (255 per packet, `requestCacheMisses :3149`) and the sim replies with full/compressed updates.
- On disk (`newview/llvocache.cpp`): directory `objectcache/`, index `object.cache` with a version/address-size header and up to `MAX_NUM_OBJECT_ENTRIES = 128` region slots (`:1178-1185`, `:1237-1255`), one file per region `objects_<x>_<y>.slc` (`:1178`) keyed by region handle and the handshake `CacheID`, written at `saveObjectCache` (`llviewerregion.cpp:858`, on region removal/logout) and read in `loadObjectCache` (`:832`, after the handshake). Entry record: 6 × S32 header `{local_id, crc, hit_count, dupe_count, crc_change_count, size}` followed by `size` bytes of compressed-update blob (`ENTRY_HEADER_SIZE :48`, reader `:210-250`, writer `:452-454`). A parallel `objects_<x>_<y>_extras.slec` stores GLTF material overrides as LLSD (`LLGLTFOverrideCacheEntry`, `:62-150`, `readGenericExtrasFromCache :1639`, `writeGenericExtrasToCache :1950`). The cache is read-only when multiple viewer instances share it (`LLVOCache(bool read_only)`).

### 3.5 How an object becomes draw calls (rebuild scheduling)
1. `gPipeline.addObject(vobj)` (`newview/pipeline.cpp:2082`) queues it in `mCreateQ`; `createObjects(max_dtime)` (`:2096`) → `createObject` (`:2120`) → `vobj->createDrawable(&gPipeline)` (`LLVOVolume::createDrawable`, `llvovolume.cpp:1171`: sets render type, creates faces per TE, picks the partition) → `markRebuild(drawable, REBUILD_ALL)`.
2. Any state change calls `gPipeline.markRebuild(drawablep, flag)` (`pipeline.cpp:3267-3286`): the drawable is pushed on `mBuildQ1` with `IN_REBUILD_Q`, and `REBUILD_VOLUME|POSITION` also sets `LLXform::SILHOUETTE`. Moves go through `markMoved` (`:3089`) → `mMovedList`; `updateMove` (`:2278`, called from `idle()` `llappviewer.cpp:6262`) applies damped/undamped movement, updates octree membership (`PARTITION_MOVE`), and shifts.

### 3.6 Volumes, sculpts, meshes and LOD

- **Mesh assets** (`newview/llmeshrepository.cpp/.h`, 6,518 + 1,000 lines): `gMeshRepo` (main-thread façade, `llmeshrepository.h:858`) + `LLMeshRepoThread : LLThread` (`:435`) + an `LL::ThreadPool` for decode (`mMeshThreadPool`, `llmeshrepository.cpp:1648`) + `LLMeshUploadThread` (`:679`) + `LLPhysicsDecomp : LLThread` (`:116`, HACD). `LLMeshRepository::loadMesh(vobj, params, new_lod, last_lod)` (`:4482`) queues a header request if unknown, else a LOD request; the thread `run()` (`:1035`) services `mHeaderReqQ`, `mLODReqQ`, `mSkinRequests`, `mDecompositionRequests`, `mPhysicsShapeRequests` bounded by `sRequestHighWater`. ## 4. Textures

### 4.0 Pipeline at a glance
1. **Creation.** `getFetchedTexture(uuid)` creates the texture object and adds it to `gTextureList`.
2. **Fast cache.** The main thread first reads a 16×16 raw thumbnail from `FastCache.cache`.
3. **Per-frame scheduling.** `LLViewerTextureList::updateImagesFetchTextures` works through a round-robin slice of textures; for each it recomputes `mMaxVirtualSize` (on-screen pixel coverage adjusted by the memory-pressure discard bias), computes `mDesiredDiscardLevel` (`processTextureStats`), and calls `updateFetch()` → `LLTextureFetch::createRequest(desired_discard)`.
4. **Fetch worker thread.** `LLTextureFetchWorker`: disk cache read (`LLTextureCache` thread) → HTTP byte-range GET (UDP on OpenSim only) → decode request (`LLImageDecodeThread` pool, OpenJPEG or KDU, reduced resolution = discard level) → cache write.
5. **Back on the main thread.** `updateFetch()` polls `getRequestFinished`; a finished raw image is uploaded on the `LLImageGLThread` shared context or pushed to `mCreateTextureList` for main-thread upload.
6. **Under memory pressure** the bias rises and textures are downscaled on the GPU through `mDownScaleQueue`.

### 4.5 Priority and budget: the actual algorithm
There is no `calcDecodePriority`/`mDecodePriority` in this version (stale comment `llviewertexture.h:515`).
- Per-frame driver (`newview/llviewerdisplay.cpp:570-582`): `LLViewerTexture::updateClass()`, then `gTextureList.updateImages(max_time)` splitting its budget (≥33% each) across `updateImagesLoadingFastCache`, `updateImagesFetchTextures`, `updateImagesCreateTextures` (`llviewertexturelist.cpp:837-905`).
- Round-robin (`updateImagesFetchTextures`, `:1275-1345`): `max(32, N/20)` textures per frame × bias when over budget; walks `mUUIDMap` from `mLastUpdateKey`; per texture `updateImageDecodePriority` then `updateFetch`. No global sort.
- Virtual size (`updateImageDecodePriority`, `:927-1105`), only for boost < HIGH: per face (≤1024 faces) `calcPixelArea` refreshed every 10 frames gives pixel area, in-frustum flag and `mImportanceToCamera` (`newview/llface.cpp:2520-2560`); importance = distance weight (16/32/48/96 m → 1/0.5/0.2/0.05) × angle weight (10°/20°/30°/beyond → 1/0.8/0.64/0.36), 0 if camera moves faster than 10 m/s or 1 rad/s (`llface.cpp:2597-2633`); `vsize = pixelArea / clamp(minTEScale², 0.0095, 25)` (texture repeats). Bias scaler `bias = round(4^(clamp(maxDiscard−2, 1, sDesiredDiscardBias) − 1))`, applied to off-screen faces always and to on-screen faces when `sDesiredDiscardBias > 1.9 + importance/2`. In-frustum faces × `max(importance × TextureCameraBoost (8), 1)`. `max_vsize` = max over faces; >1024 faces → `MAX_IMAGE_AREA`. Unboosted LOD textures have `mMaxVirtualSize` reset to 0 when bias > 1.5, or off-screen and bias > 1.0. `addTextureStats(max_vsize)` keeps the running max, capped at 8192² (`llviewertexture.cpp:970-984`).
- Desired discard (`LLViewerLODTexture::processTextureStats`, `llviewertexture.cpp:3181-3304`): caps vsize to `RenderMaxTextureResolution²` (default 2048; 512–2048) for boost < HIGH; `vsize ≤ 10` → discard `MAX+1`; otherwise `discard = floor(log4(texelsPerImage / vsize))` (or known draw size), clamped to `[0 or 1, 5]` then to `mMinDesiredDiscardLevel`; if current is better than desired and boost < `AVATAR_BAKED`, `scaleDown()` enqueues a GPU downscale; `BOOST_SELECTED` restored after consumption (FS FIRE-36016).
- Fetch decision (`updateFetch`, `:2149-2383`): request only if priority > 0, desired ≤ max discard, current worse than desired, and no equal-or-better request in flight. `createRequest` passes desired discard and GL w/h for byte-range sizing.
- Memory pressure (`LLViewerTexture::updateClass`, `:501-670`): `used` = texture bytes + VB bytes, both ÷ 512 KB (deliberate doubling because counters undercount, `:523-527`). Budget default `max(1024, VRAM/RenderTextureVRAMDivisor)`; with FS `FSLimitTextureVRAMUsage`: `RenderMaxVRAMBudget` (`:529-535`). Target `max(min(budget−512, 0.8·budget), 768)`; `sFreeVRAMMegabytes = target − used`; `over_pct = (used − target)/target`. Entering low memory (VRAM over target or system memory low; FS adds Windows commit charge, `:690-787`): bias slammed to ≥ 1.5; if system memory low or `over_pct > 2`, `updateImageDecodePriority` runs over every texture immediately. While low: bias += `(0.1 + over_pct)`/s. ≥10% under target and recovered: bias −≈0.1/s. Background/minimized: bias → 5 after 60 s / 1 s. Clamp [1, 4]. Actual freeing: downscale queue in `updateImagesCreateTextures` (≥5 per frame, even past the budget, `llviewertexturelist.cpp:1170-1211`) → `LLImageGL::scaleDown` (FBO blit via `mDownResMap` + `gCopyProgram`, or mip-N readback via scratch PBO and re-specify; `llrender/llimagegl.cpp:2468-2560`). Textures are not evicted outright except through the 30 s zero-reference lazy flush.

### 4.6 Upload to GL (`llrender/llimagegl.cpp`)
- `LLImageGLThread` is a one-thread `LL::ThreadPool("LLImageGL")` with a shared context from `LLWindow::createSharedContext`; FS disables it if context creation fails (`:2635-2668`). - `createGLTexture` (`llimagegl.cpp:1532-1743`): format from component count L8/LA8/RGB8/RGBA8; off main thread always generates a new GL name, sets `BASE_LEVEL=0`, `MAX_LEVEL = maxDiscard − discard`, `setImage`. `syncToMainThread` (`:1745-1798`): NVIDIA fence + `glClientWaitSync`, others fence + `glWaitSync` on the main queue; then `syncTexName` swaps `mTexName` and deletes the old name on main. Mipmaps via `glGenerateMipmap` in core profile (`:836-875`); hand-made mip path exists (`:877+`).
- Compression: `sCompressTextures` (from `RenderCompressTextures`, `llappviewer.cpp:626`) maps internal formats to `GL_COMPRESSED_*` (`:1416-1460`); off for VRAM > 512 MB (`featuretable.txt:400`). ### 4.10 Keep / avoid
**Keep:** progressive J2C by discard level (range-fetch only the bytes needed, decode at reduced resolution, reuse and extend the downloaded prefix); the 1-byte overlapping range trick and tolerant 206/200/416 handling; screen-coverage-driven desired resolution (`log4(texels/pixels)`, texture-repeat correction, importance-to-camera boost, user cap); a single global "discard bias" control loop driven by measured VRAM and system memory with hysteresis and fast slam, freeing memory by GPU-side downscaling rather than refetching; two-tier disk cache (fixed-slot header store + body files + tiny raw thumbnail tier) with time-sliced LRU purging; decode on a pool, upload on a worker with explicit fence-based handoff and deferred GPU deletion (Vulkan: timeline semaphores and per-frame deletion queues); round-robin, bounded per-frame priority updating.

**Avoid:** ref-count-based eviction heuristics (`numRefs <= 3`) and ordinal-coupled states (`isActiveFetching` magic numbers); a worker state machine that re-polls with sleeps/deferrals and a dozen interlocking mutexes (use async tasks/channels); a "priority" that does not order work (the fetch queue is FIFO despite carrying priorities — use real priority queues for fetch, decode and upload); synchronous mutex-heavy disk I/O on the main thread (fast cache, purge on the write-issuing thread) and a packed C-struct on-disk format without checksums; doubling allocation counters to estimate VRAM (query `VK_EXT_memory_budget`); driver-side `GL_COMPRESSED_*`, `glGenerateMipmap` on the upload context, per-vendor upload hacks (prefer offline or worker-side BCn transcoding and compute/blit mip generation); global singletons (`gTextureList`, `LLAppViewer::getTextureFetch()`) reached from deep inside per-texture logic.

### 5.12 Keep / avoid
**Keep:** data-driven skeleton/params/attachments from the two XML files with aliases, base vs extended support, and stable joint numbering (bones, then collision volumes, then attachment ids); **param order as protocol** (positional U8 array over TWEAKABLE + TRANSMIT_NOT_TWEAKABLE params in file order, quantised over [min,max] — hard-code tests); the `ATTACHMENT_ID_FROM_STATE` nibble swap and `ATTACHMENT_ADD` stripping; exact .anim deserialisation with U16 quantisation ranges (rotation ±1, position ±5 m, time 0..duration) and limits (60 s, 10 constraints); the SSA flow (COF version, POST to `UpdateAvatarAppearance`, retry on `expected`, stale-version rejection, bake URLs from the AppearanceService); joint-override semantics (per mesh UUID, deterministic winner, full-rig threshold, pelvis fixup, lock-scale); per-frame per-skin-hash palette caching and 3x4 packing (an SSBO lifts the 110-joint limit internally while preserving it for compatibility); priority- and weight-capped joint-state blending plus an additive pass; the procedural motion set; complexity/jellydoll policy and impostors (keep the ARC formula so numbers match other viewers).

**Avoid:** the multiple-inheritance god object (`LLVOAvatar` mixes network object, renderer, animation, UI tags and policy — split into components: skeleton, appearance, attachments, animation, render proxy, nametag); static global XML info and singleton dictionary, raw owning pointers, `LL_ERRS` on malformed data (a corrupt lad file aborts, `llvoavatar.cpp:8209`); the Legacy Bake / client compositing path unless OpenSim is a hard requirement (it carries a full GL compositor and upload pipeline); separate system-body skinning (15-joint, 1-weight lerp) alongside mesh skinning — unify on one 4-influence path; implicit "largest UUID wins" override resolution and appearance-version ambiguity (field vs param 11000) — encode explicitly; per-avatar perspective impostor RTs regenerated on frame counters (consider atlas-based impostors with explicit invalidation keys); FS feature flags scattered through core logic via `LLCachedControl` (centralise mute/friends-only/RLV/exclusion policy into one evaluator).


## 6. Audio, voice and streaming media

**Bottom line:** the server sends world audio as *events*: asset UUID, owner/object IDs, a 0..1 gain, flags, a cutoff radius, and a region-local position (only for one-shot triggers). Everything that makes sound spatial happens in the client: per-frame source positions and velocities, listener placement, distance attenuation, channel priority, parcel and mute gating, doppler and rolloff. Two exceptions: media-on-a-prim gets distance-based volume only (no direction), and WebRTC voice is mixed and spatialized on the server (the viewer only sends positions).

### 6.1 llaudio core

**Engine constants and gain classes**
- 30 logical channels, 60 decoded buffers (Firestorm raised buffers from 40): `llaudio/llaudioengine.h:57-60`. `ATTACHED_OBJECT_TIMEOUT=5`, `DEFAULT_MIN_DISTANCE=2.0` (`llaudio/llaudioengine.h:54-55`); `DEFAULT_MIN_DISTANCE` is never used anywhere.
- Gain classes: `AUDIO_TYPE_NONE=0, SFX=1, UI=2, AMBIENT=3` (`llaudio/llaudioengine.h:81-85`). Each class has a secondary gain (`mSecondaryGain[]`, `llaudio/llaudioengine.cpp:108-109`, setter `:712-717`), picked up in `LLAudioChannel::updateBuffer` (`:1863`). Final per-voice volume = `secondaryGain * source->getGain()` (FMOD `llaudio/llaudioengine_fmodstudio.cpp:730`; OpenAL `llaudio/llaudioengine_openal.cpp:284-285,336`).
- Master gain → FMOD master channel group (`llaudioengine_fmodstudio.cpp:660`) or OpenAL listener `AL_GAIN` (`llaudioengine_openal.cpp:185`). Mute forces internal gain to 0 (`llaudioengine.cpp:696-705`). `init()` only calls `setDefaults()` and `allocateListener()` (`:113-124`).

**`LLAudioEngine::idle()` and channel allocation** (`llaudio/llaudioengine.cpp:239-494`)
1. Marks all buffers unused (`:247-253`).
2. For every source: `update()`, `updatePriority()`, delete if `isDone()` (`:258-272`). Among sources with a decoded buffer but no channel, remembers the single highest-priority one (`:280-288`).
3. Only that one source gets a channel per idle tick via `getFreeChannel(max_priority)` (`:297-317`); sync slaves are flagged waiting (`:305-314`). (`LLAudioSource::play()` → `setupChannel()` can also grab a channel immediately: `:1475-1518`, `:1582`.)
4. `getFreeChannel` (`:590-642`): unallocated slot, else a slot neither playing nor waiting, else evicts the lowest-priority playing channel if its priority ≤ requester's (`:618-641`).
5. Priority formula (`:1448-1473`): forced priority (UI/preview) = 1.0; muted = 0; otherwise `mGain / max(1, |pos − listenerPos|²)`. The channel-limit policy is purely client-side.
6. `updateChannels()` (buffer swap, `update3DPosition`, `updateLoop`; `:225-237`), then queue processing (`:326-401`): a source with `mQueuedDatap` promotes it when the channel finished (`:365-384`) or, for loops, when `mLoopedThisFrame` is set (`:387-400`).
7. `updateChannels()` again (`:406`).
8. Sync: one *global* sync master = highest-priority non-muted source with the sync-master flag (`:408-421`). When its channel loops, every waiting slave starts with `playSynced(master)` (`:423-455`). FMOD copies the master's PCM position (`llaudioengine_fmodstudio.cpp:838-854`); OpenAL copies `AL_SEC_OFFSET` (`llaudioengine_openal.cpp:225-242`).
9. `commitDeferredChanges()` (`:458`); buffers unused for 30 s flushed (`:461-473`); loop flags cleared (`:477-483`).
10. Decode queue (`:486`), next asset transfer (`:491`), stream update (`:493`).

Loop detection in both backends is "sample position went backwards", which the code itself calls a hack (`llaudioengine_openal.cpp:296-312`; `llaudioengine_fmodstudio.cpp:781-800`).

Asset fetch order (`startNextTransfer`, `:1031-1227`): one transfer at a time, highest-priority source first: current data on live channels, then queued data, then preloads, then everything else.

**`LLAudioSource`** fields (`llaudio/llaudioengine.h:381-400`): `mPositionGlobal` (LLVector3d), `mVelocity`, `mGain` (clamped 0..1, `:345`), `mLoop`, `mSyncMaster/Slave`, `mQueueSounds`, `mForcedPriority`, `mSourceMuted`, `mType`, `mCurrentDatap/mQueuedDatap`, `mPreloadMap`. - Queueing (`addAudioData`, `:1670-1742`): queue is one slot deep (new sound dropped if `mQueuedDatap` set, `:1700-1705`); same sound not re-queued while looping (`:1707-1711`); without queueing a new sound replaces the current buffer immediately (`:1718-1734`); `set_current=false` → preload map (`:1736-1741`).
- Expiry (`isDone`, `:1600-1667`): corrupted dies immediately; loops never die on their own; pending preloads/queued keep alive; no channel → 15 s (11 s if muted) or once played; playing → hard cut at 60 s. `play(null)` is the stop idiom (`:1538-1554`).

### 6.8 Server-provided vs client policy

| Spatial-audio input | Server provides | Client policy |
|---|---|---|
| Trigger sound position | Region handle + region-local `Position` (`llviewermessage.cpp:4928-4937`) | Fixed after trigger; converted to global F32 |
| Attached sound position | Nothing audio-specific (object position from ObjectUpdate) | Sampled every frame from interpolated object position; avatar root for attachment cutoff; camera for HUDs (`llaudiosourcevo.cpp:243-259,:55-71`) |
| Source velocity (doppler) | Object velocity in ObjectUpdate | Triggers: none. Attached: object/sub-parent velocity |
| Gain | `Gain` 0..1 on trigger, attached, gain-change, ObjectUpdate | Clamped; × class gain × master |
| Loop / sync / queue / stop | `Flags` byte (`lldefs.h:128-135`) | Single global sync master; 1-deep queue; loop detection by position wrap |
| Cutoff radius | ObjectUpdate `Radius` | Distance to ear (camera/avatar); <0.1 m = off |
| Parcel "sound local" | Parcel flag + overlay bit | Enforced client-side (`llviewerparcelmgr.cpp:861-887`) |
| Mute / blacklist / antispam | none | Client only |
| Listener position/orientation | none | Camera or avatar position; camera orientation; agent velocity |
| Distance attenuation curve | none | FMOD/AL default inverse model, rolloff 1 (5 underwater), doppler 1, min/max never set |
| Channel limit / priority | none | 30 channels, `gain/d²`, one new assignment per tick |
| Wind | Region wind vector | Synthesis, mapping, fades all client-side |
| Footsteps | none (animation state only) | Client-generated, AMBIENT, gain 0.1 |
| Collision sounds | `SoundTrigger` with material UUID | Toggle `EnableCollisionSounds` |
| Parcel music | `MusicURL` in ParcelProperties | Autoplay/filter policy; 2D stream |
| Prim/parcel media audio | Media URL / MOAP data | Plugin-rendered; scalar volume 40–80 m rolloff; no panning |
| Voice (WebRTC) | Stereo pre-mixed spatialized stream; peer power/join/leave | Sends own avatar+listener positions (cm ints) via data channel; 50 m tether; per-peer gain/mute requests |
| Voice (Vivox) | SDK/server mixing | Sends speaker and listener 3D positions |

### 6.9 Keep / avoid
**Keep:** mono world sounds (decoded assets always mono 44.1 kHz, ideal HRTF point sources); source model {position, velocity, gain, loop, sync-master/slave, 1-slot queue, preload set, expiry timers} keyed by object ID, re-sampling the interpolated object position every frame; priority `gain/d²` with eviction, cutoff radius, parcel sound-local/mute/maturity gates (user-visible behaviour); ear-location choice and 2D path for UI/preview/HUD; highest-priority-first asset fetch, off-thread decode with on-disk cache, corrupt-asset retry cap, loop-boundary micro-fade; the wind synthesis algorithm fed by region wind minus agent velocity; the WebRTC data-channel position protocol and tether exactly as the server expects; per-class gain buses.

**Avoid:** one new channel per tick and loop detection by sample-position wrap (use real end/loop callbacks, sample-accurate sync); implicit backend distance defaults (define min distance and rolloff explicitly so HRTF/distance cues match SL loudness); global coordinates as F32 in the audio engine (use listener- or region-relative frames); camera orientation mixed with agent velocity for the listener; the single global sync master (scope per linkset/owner); hardcoded mono/44.1k WAV header without validating (parse Vorbis info); expecting per-speaker positional voice from WebRTC (the SL server sends a pre-spatialized stereo mix; HRTF voice needs server changes — treat voice as a stereo bed); treating media audio as spatial (CEF bypasses the engine; HRTF for MOAP needs plugin audio capture).

### 7.1 Command reception, parsing, replies, versions

#### 7.1.1 Where commands come in
- **Entry point:** `process_chat_from_simulator()` at `newview/llviewermessage.cpp:2769`, which handles the ChatFromSimulator message. The RLV hook sits in the `CHAT_TYPE_OWNER` branch at `newview/llviewermessage.cpp:3140-3216`.
- **Firestorm handlers that run first** in that branch:
  - the LSL client bridge, `FSLSLBridge::lslToViewer` (`llviewermessage.cpp:3125-3131`);
  - `cmdline_packager` (`:3134`).
- **Conditions for a message to be treated as RLV** (`llviewermessage.cpp:3142-3143`):
  - RLV is enabled;
  - the message is longer than 3 characters and starts with `RLV_CMD_PREFIX` (`'@'`, `newview/rlvdefines.h:81`);
  - the chat type is `CHAT_TYPE_OWNER` (i.e. llOwnerSay);
  - the sender is not a temporary attachment, unless `RLVaEnableTemporaryAttachments` is set.
- **Pre-processing:** the `@` is removed and the text is lower-cased (`:3145-3146`). It is then split on `,` with `boost::char_separator(",")` (`:3150`).
- **Dispatch:** each token goes to `gRlvHandler.processCommand(from_id, strCmd, true)` (`:3155`). `from_id` is the UUID of the speaking prim, and that UUID becomes the restriction's owner.
- **After the batch:** `RlvForceWear::instance().done()` flushes queued force-wear actions (`:3182-3183`). The chat line is then swallowed. If `RestrainedLoveDebug` is on, it is instead rewritten as "executes/failed/retained: @…" (`:3185-3215`).
- **Firestorm's "own object" spam check** is deferred for owned objects "so RLV commands still work" (`:2976`).
- **Script-chat particles** are suppressed for owner-say while RLV is on (`:2909-2916`).
- **Second entry point (IM queries):** `process_improved_im` → `newview/llimprocessing.cpp:961-962` calls `RlvHandler::processIMQuery` (`newview/rlvhandler.cpp:652`). It handles `@stopim`, plus `@version`, `@list` and `@except`; the last three need `RLVaEnableIMQuery`. Replies go out as do-not-disturb auto-response IMs via `RlvUtil::sendBusyMessage` (`newview/rlvcommon.cpp:714-723`).
- **Third entry point (local console):** `RlvFloaterConsole::onInput` sends commands as `gAgent.getID()` (`newview/rlvfloaters.cpp:837`, `:864`). Closing the console issues `@clear` (`:828`).

#### 7.1.2 Parsing
- **Syntax:** `RlvCommand::parseCommand` (`newview/rlvhelper.cpp:760-790`) accepts `<behaviour>[:<option>]=<param>`.
  - It finds the first `=`, then a `:` that comes before it.
  - `clear` is the one command allowed to have no `=` (`:777-781`).
- **Param type**, decided in `RlvCommand::RlvCommand` (`rlvhelper.cpp:721-751`):
  - `n` or `add` → `RLV_TYPE_ADD`
  - `y` or `rem` → `RLV_TYPE_REMOVE`
  - behaviour `clear` → `RLV_TYPE_CLEAR`
  - `force` → `RLV_TYPE_FORCE`
  - any value that parses as an S32 → `RLV_TYPE_REPLY` (the number is the reply channel)
  - anything else → invalid.
- **Lookup:** after the type is set, the behaviour is looked up in `RlvBehaviourDictionary::getBehaviourInfo` (`rlvhelper.cpp:436-457`). Two suffix rules apply:
  - `_sec` means a strict variant. It is only accepted if the entry has `BHVR_STRICT`.
  - For force commands, an unmatched `<bhvr>_<suffix>` is tried as a local modifier, e.g. `@setsphere_distmin:2=force`.
- **Return codes** are `ERlvCmdRet` (`newview/rlvdefines.h:328-352`). They include RETAINED, SUCCESS_UNSET/DUPLICATE/DELAYED, and FAILED_SYNTAX/OPTION/PARAM/LOCK/DISABLED/UNKNOWN/NOSHAREDROOT/BLOCKED/THROTTLED.

#### 7.1.3 Dispatch (`RlvHandler::processCommand`, `newview/rlvhandler.cpp:455-591`)
- **Rejections up front** (`:462-476`):
  - commands from blocked objects, except rem/clear;
  - invalid syntax;
  - behaviours flagged `BHVR_BLOCKED`.
- **Command and object stacks** are pushed (`:481`). This is what lets `@tpto` know its issuer later.
- **ADD** (`:486-540`):
  - `@setcam`, `@setdebug` and `@setenv` can only be held by one object at a time; a second object gets `RLV_RET_FAILED_LOCK` (`:496-502`).
  - Otherwise an `RlvObject` is found or created, the command is added, and `processAddRemCommand` runs. A failure rolls the add back.
- **REMOVE** (`:541-565`) removes the command and erases the object once its command list is empty.
- **CLEAR, FORCE and REPLY** go to their own processors (`:566-574`).
- **Listeners:** `m_OnCommand` fires at `:581`. It is used by the floaters and by `RlvBehaviourNotifyHandler`.
- **Before login completes:** `processCommand(idObj, string)` (`:594-603`) queues commands in `m_Retained` while the startup state is not `STATE_STARTED`.

#### 7.1.4 How replies are sent
- **The function:** `RlvUtil::sendChatReply` (`newview/rlvcommon.cpp:726-744`) builds a **`ChatFromViewer`** message by hand ("Copy/paste from send_chat_from_viewer()"). It uses `Type = CHAT_TYPE_SHOUT`, `Channel = nChannel`, and the text truncated to `MAX_MSG_STR_LEN`. It does not use ScriptDialogReply.
- **Channel rule:** `isValidReplyChannel` (`newview/rlvcommon.h:340-343`) requires a channel above 0 and not `CHAT_CHANNEL_DEBUG`. "Loopback" mode, used when the issuer is the agent, also allows channel 0.
- **Splitting:** `sendChatReplySplit` (`rlvcommon.cpp:746`) splits long replies.
- **Who calls it:**
  - reply-type commands: `RlvCommandHandlerBaseImpl<RLV_TYPE_REPLY>::processCommand` (`rlvhandler.cpp:3424-3446`) and the older switch-based reply path (`:3561-3567`). On channel 0 the reply goes to the console floater (`:3437-3441`).
  - `@redirchat` / `@rediremote` (`rlvhandler.cpp:1308-1335`).
  - `@notify`, as `"/"+text` on the listener's channel (`newview/rlvhelper.cpp:1919`).
  - the `getenv_*` / `getdebug_*` extension handlers.

  | `RlvBehaviourHandler` / `RlvBehaviourToggleHandler` | `RlvCommandHandler<RLV_TYPE_ADDREM, X>` |
  | `RlvForceHandler` | `RlvCommandHandler<RLV_TYPE_FORCE, X>` |
  | `RlvReplyHandler` | `RlvCommandHandler<RLV_TYPE_REPLY, X>` |

  These are glued together by `RlvCommandProcessor` (`:198-216`), with generic handlers per option type at `:219-222`.
- **Reference counting:** the shared base `RlvCommandHandlerBaseImpl<RLV_TYPE_ADDREM>::processCommand` (`newview/rlvhandler.cpp:1746-1783`) increments or decrements `m_Behaviours[eBhvr]`, a per-behaviour S16 count (`newview/rlvhandler.h:250`). It also:
  - records `_sec` commands as `RLV_BHVR_PERMISSIVE` exceptions;
  - fires `m_OnBehaviour`;
  - fires the toggle handler and `m_OnBehaviourToggle` on 0↔1 transitions.
- **Query function:** `hasBehaviour(e)` is `m_Behaviours[e] != 0` (`newview/rlvhandler.h:59`).
- **Older commands** without a processor go through the switch-based paths: `processAddRemCommand` (`rlvhandler.cpp:1591-1743`), `processForceCommand` (`:2834-2909`) and `processReplyCommand` (`:3449-3570`).
- **Unknown behaviours** are offered to registered `RlvExtCommandHandler`s (`:1714-1716`, `:2900-2902`, `:3555-3557`).

#### 7.2.3 Modifiers (`newview/rlvmodifiers.h`)
- **`RlvBehaviourModifier`** (`newview/rlvhelper.h:243-286`) keeps a list of (value, object, behaviour) tuples. A comparator decides which value is "primary": `RlvBehaviourModifierCompMin` keeps the most restrictive minimum, `...Max` the maximum (`rlvmodifiers.h:42-75`).
- **`RlvBehaviourModifierHandler<eMod>`** (`:28`) overrides `onValueChange()`.
- **`RlvCachedBehaviourModifier<T>`** (`:119`) is a cheap cached read used in hot paths, e.g. `newview/llvoavatar.cpp:4840` and `newview/rlvactions.cpp:570`.
- **Local modifiers** for `@setsphere` and `@setoverlay` are stored per `RlvObject` (`newview/rlvhelper.h:470-476`). They are registered through `RlvBehaviourInfo::addModifier(eLocalMod, typeid, "suffix", callback)` (`rlvhelper.cpp:231-249`).

### 7.3 Behaviour categories and how each is enforced

#### 7.3.1 Chat
- **Outgoing chat** has two parallel hook sites:
  - `send_chat_from_viewer` in `newview/llfloaterimnearbychat.cpp:887-930`;
  - Firestorm's copy in `newview/fsnearbychathub.cpp:104-150`.
- **What those hooks do:**
  - `@chatwhisper`, `@chatnormal` and `@chatshout` change the volume via `RlvActions::checkChatVolume` (`newview/rlvactions.cpp:269`, `fsnearbychathub.cpp:112-117`).
  - `@redirchat` / `@rediremote` try `redirectChatOrEmote` and drop the local send if it redirected (`:120-121`).
  - `@sendchat` calls `filterChat(text, true)` (`:127-128`).
  - On a non-zero channel, `canSendChannel` enforces `@sendchannel[_except]` (`:133`).
- **Typing animation** is suppressed while redirecting (`fsnearbychathub.cpp:427-428`, `llfloaterimnearbychat.cpp:735-736`).
- **Typing start:** `canSendTypingStart` is checked in `LLAgent::startTyping` (`newview/llagent.cpp:2597`).
- **Gestures:** `@sendgesture` is checked in `newview/llgesturemgr.cpp:558`.
- **Script dialogs:** `@sendchat` blocks replies to script dialogs on channel 0 (`newview/llviewermessage.cpp:8339-8351` in `callback_script_dialog`, and `newview/llnotificationscripthandler.cpp:120-131`).
- **The filter itself:** `RlvHandler::filterChat` (`rlvhandler.cpp:1263-1299`):
  - Emotes containing `"()*=^_?~`, ` -`, `- ` or `''` are filtered.
  - Without `@emote`, emotes are cut to 20 characters or at the first `.`.
  - Text starting with `/` is allowed only up to 7 characters.
  - Ordinary text is filtered unless it is `((OOC))` and `RestrainedLoveCanOOC` is set.
  - Filtered text becomes `"..."` when `RestrainedLoveShowEllipsis` is set, otherwise empty.
- **Incoming chat** is handled in `process_chat_from_simulator` at `llviewermessage.cpp:2983-3067`:
  - `@recvchat`, `@recvchatfrom`, `@recvemote` and `@recvemotefrom` (with per-UUID exceptions) filter or drop agent chat and non-own-attachment object chat. Owner-say and RegionSayTo are never filtered (`:2993-3019`).
  - `@shownames` anonymises the speaker name. Agents get `RlvStrings::getAnonym`; objects get `RlvUtil::filterNames` (`:3025-3046`).
  - Object chat gets an `objectim` SLURL with `rlv_shownames` (`:3051-3066`).
- **`RlvUtil::filterNames`** (`newview/rlvcommon.cpp:514-549`) regex-replaces the display and legacy names of every nearby avatar, then calls `filterMentions` (`:552`). Mentions are rewritten as `/agent/<id>/rlvanonym`, which `llui/llurlentry.cpp:1049-1064` renders via `rlvGetAnonym`.
- **`RlvUtil::filterLocation`** (`rlvcommon.cpp:492-511`) replaces nearby region names and the current parcel name.
- **Nearby-chat rendering** (`newview/llfloaterimnearbychathandler.cpp`) and system and notification text (`llviewermessage.cpp:6855-6903`) pass through both filters again.

#### 7.3.2 Instant messages

#### 7.3.10 Exceptions
- **Storage:** exceptions live in `m_Exceptions`, a multimap from behaviour to `RlvException{idObject, eBhvr, variant option}` (`newview/rlvhandler.h:234-249`). The option can be a UUID, an S32 channel or a behaviour.
- **Writes:** `addException` and `removeException` (`rlvhandler.cpp:270-331`) are called by the generic EXCEPTION handlers, e.g. `@sendim:<uuid>=add`, `@recvchat:<uuid>`, `@redirchat:<chan>`.
- **Checks:** `isException(e, opt, check)` (`:275-308`).
  - In Permissive mode, any object's exception counts.
  - In Strict mode, every object holding the restriction must also hold the exception. Strict applies when a `_sec` restriction exists and `@permissive` isn't set (`isPermissive`, `:311-316`).
- **`_sec` tracking:** each `_sec` add registers itself as a `RLV_BHVR_PERMISSIVE` exception (`:1758-1759`).

### 7.6 Object tracking and cleanup
- **Per-object record:** each issuing prim UUID maps to an `RlvObject` (`newview/rlvhelper.h:442-492`, stored in `RlvHandler::m_Objects`, `newview/rlvhandler.h:247`). It holds:
  - the ordered command list;
  - the attachment-point index;
  - the root UUID;
  - a lookup flag and miss counter;
  - local modifiers.
  
  Its methods are `addCommand`, `removeCommand`, `hasBehaviour` and `getStatusString` (`newview/rlvhelper.cpp:1143-1240`).
- **`onAttach`** (`rlvhandler.cpp:957-997`) resolves objects that weren't known yet and applies a pending `@detach=n` lock.
- **`onDetach`** (`:1000-1051`): if the object was dropped in-world it only releases the detach lock; if it was really detached it issues `processCommand(id,"clear")` for every RlvObject whose root matches.
- **Garbage collection:** `RlvGCTimer` runs every 30 s (`newview/rlvhelper.h:654-659`, `rlvhelper.cpp:1975`) and calls `onGC` (`rlvhandler.cpp:1086-1153`):
  - an object that once existed in `gObjectList` and is now gone is `@clear`ed;
  - an object never seen is cleared after more than 20 misses (about 10 minutes);
  - it also verifies attachment locks and prunes stale blocked temp attachments.
- **`@clear[=filter]`** (`processClearCommand`, `rlvhandler.cpp:623-650`) replays `<cmd>=y` for each of the issuer's commands whose string contains the filter. It then notifies extension handlers. It always returns success.
- **Empty objects** have their modifiers cleared and the RlvObject erased (`:557-562`).

### 7.9 Minimal interception-point list for a new viewer

**A. Command ingress and egress**
1. Owner-say chat (`CHAT_TYPE_OWNER`) starting with `@`. Strip the `@`, lower-case, split on `,`, and dispatch keyed by source-object UUID. This must run before mute, spam and "LSL bridge" consumers swallow the chat.
2. Queue commands before login completes; answer `@version*` during login.
3. Reply sink: `ChatFromViewer` with SHOUT on a positive channel; a split helper for long replies.
4. IM-query ingress for `@version`, `@list`, `@except` and `@stopim`; an IM busy-reply sink.
5. Object lifecycle events: attach, detach (before removal), "dropped to world", object kill, and a periodic sweep. Missing objects trigger `@clear`.

**B. Chat and IM**
6. Outgoing local chat pre-send: volume clamp, sendchat filter, redirect, channel allow-list, typing indicator, gesture playback, script-dialog replies.
7. Incoming local chat post-receive: recvchat/recvemote filter, speaker-name anonymisation, mention and location scrubbing.
8. IM send and session start (P2P, group, conference); IM receive with busy reply; offer and lure payload text.

**C. Movement, teleport, sit**
9. All teleport requests (landmark, location, lure accept, request, home, map, autopilot), with "local" vs "remote" classification and a force-TP bypass. Also the TP-cancel availability flag.
10. Sit and stand requests (object, ground) with source-position capture; stand-up control flags; the sit/stand-completed event.
11. Fly, jump, always-run and temp-run state setters; AFK auto-clear.

**D. World interaction**
12. A single `canTouch` / `canInteract` / `canSit` / `canEdit` / `canBuy` / `canPay` predicate consulted by click, grab, hover-cursor, tooltip, selection, build, rez, drag-drop, delete/return, menus and media focus. Include the fartouch distance and HUD vs world vs attachment rules.
13. Overlay hit-test mask in screen picking.

**E. Appearance and inventory**
14. Attach, detach and wear/remove requests, at item level and attachment-point level, including the "attach-from-world" path, plus a re-attach watchdog.
15. Inventory move, rename, delete, paste and give operations against folder locks and the `#RLV` subtree. Give-to-`#RLV` routing of incoming folder offers.
16. Asset-viewer opens: notecard, script, texture preview.

**F. Perception and UI**
17. A central floater/panel "may open?" gate covering inventory, maps, minimap, about-land, region info, environment editors, buy/pay, and the viewXXX floaters.
18. Name presentation service: avatar name tags (with distance), people lists, radar, minimap, inspectors, notifications and SLURL rendering (an anonymised-agent URL scheme).
19. Location presentation service: status bar, location bar, window title, map labels, teleport history, hover text.
20. Hover-text filter per object (HUD vs world).

**G. Camera and render**
21. Camera position solver: avatar and origin distance clamps, focus lock, eye/focus offset presets, FOV clamp, mouselook gate, exclusive camera-preset ownership.
22. Render hooks: far-clip clamp for picking; world texture override for unattached faces; avatar silhouetting beyond distance; a post-process sphere pass after AA and before vignette; a full-screen overlay pass after HUD elements and before HUD attachments; self-avatar/head visibility.

**H. Environment and settings**
23. The environment selection setter, which locks non-RLV environment changes; a get/set API for named sky parameters.
24. A whitelisted debug-setting get/set; script-permission requests (auto-grant, and strip attach/teleport); active-group change with a throttle.
25. A login-location override and persisted per-account "login at last location" flag.

The single most important design point: each of these is a **query to one policy service**. The answers are refcounted behaviours, per-UUID exceptions with strict/permissive semantics, and min/max-composited modifiers. There should also be **change signals** (behaviour toggled, modifier changed), which RLVa uses to reconfigure UI, camera and render state.

### 8.10 Keep / avoid
**Keep:** flat `id → object` map with parent→children indexes and a backlink index, and the version/descendent-count "complete" rule; the cache format idea (versioned header + binary LLSD + gzip), validated per folder against the skeleton version, dropping broken-link folders; AIS3 as the only write path on SL with `_updated_category_versions`-driven accounting; COF as a links-only folder replaced atomically with SlamFolder (PUT `/links`), its version as the bake key (`cof_version` → `UpdateAvatarAppearance`); breadth-first, front-prioritised fetch queue with batched subset fetches and an in-flight cap; time-sliced parsing of large AIS responses; restriction enforcement (1 body part per type, clothing cap, dedupe) as a pure function over COF contents; the two-stage upload with fresh uploader on retry, `?type_id=` asset URLs, and the `RequestTaskInventory` cap with serials and 304.

**Avoid:** global singletons with re-entrant `notifyObservers` and backlog hacks (use an event queue or diff-based delivery); optimistic `accountForUpdate` bumps that put the viewer ahead of the server (FS FIRE-33455, `llviewerinventory.cpp:1747-1754`); duplicated UDP/HTTP/AIS code paths behind `#ifdef` (one transport trait; keep UDP only for what SL still requires: `CreateInventoryItem`, `CopyInventoryItem`, `MoveInventoryItem`, `RezMultipleAttachmentsFromInv`, IM offers, Transfer/Xfer fallbacks); `shadow_id` XOR and the legacy text task-inventory format except as compatibility parsers; polling holding patterns with superseded-request flags (cancellable futures keyed by COF version); hard-coded batch sizes (1 attachment per packet, 10 per legacy fetch).

### 9.8 Separability verdict and recommendation
- Wire/protocol layers: separable now. Viewer model layer: entangled widely (1,179 notification calls, 260 files using `LLFloaterReg`, 202 using `gViewerWindow`); protocol replies bound to notification template names; localized strings produced inside network handlers.
- XUI is a large but self-contained retained-tree toolkit (~100k lines C++ + ~180k lines XML, 13 languages, 8 skins) that rebuilds GL-immediate geometry every frame, no atlas, no batching beyond a VB hash cache.
- **Re-implement the UI; do not translate XUI.** (1) Port model and network layers first behind an event bus: each `LLNotificationsUtil::add` and `LLFloaterReg::show` in `process_*` becomes a typed domain event (`ScriptDialogRequested{…}`, `OfferReceived{…}`); replies become explicit commands. (2) Keep `notifications.xml` and `strings.xml` as data to drive the new notification/localization system (1,363 templates and 2,497 strings with translations). (3) Do not port `LLInitParam`, `LLView`, `LLFloaterReg`; rebuild in a Rust toolkit with batched, atlased rendering. Floater/panel XML could be converted once by a tool, but expect to redesign by hand — 258 floaters + 231 panels is the single largest porting cost. (4) Preserve external contracts: the `secondlife:///app/*` command set (~40 commands), the chat-log text format, `open_notifications_<grid>.xml` semantics, the LEAP stdin/stdout LLSD protocol, and the out-of-process media-plugin model (socket + shared-memory frames), which can be reused as-is with the existing SLPlugin/CEF binaries.

### 10.3 Frame timing
`gFrameTime/gFrameTimeSeconds/gFrameIntervalSeconds` (`llcommon/llframetimer`), `gFrameDTClamped` (clamped to 1..200 fps, `:5906-5914`), `gFPSClamped` EMA (`:5918`); time-sliced jobs everywhere take an explicit `max_time` (`updateRegions` 1 ms, texture list `max_time`, `createObjects`, `updateGeom`, `LLMeshRepoThread::mWorkQueue.runFor(8 ms)` `llmeshrepository.cpp:1052`). There is no fixed-timestep simulation; object interpolation integrates with the real frame delta (`LLViewerObject::idleUpdate`, `llviewerobject.cpp:2541-2560`). `LLPerfStats` (`newview/llperfstats`) does the FS/LL "auto-tune" (adjusting draw distance / avatar complexity to hit a target frame time) at the top of `doFrame` (`:1583-1586`). Watchdog: `pingMainloopTimeout/pauseMainloopTimeout` around blocking sections (`LLWatchdog`, `llcommon/llwatchdog.h`).


## 11. Grid and simulator specifics that constrain the architecture

### 11.1 Regions, coordinates, neighbours
- The world is a grid of 256 m regions addressed by a 64-bit **region handle** = `(x_meters << 32) | y_meters` (`from_region_handle/to_region_handle`, `llmath/`); `REGION_WIDTH_METERS = 256` (`llcommon/indra_constants.h:37`), height 4096 (`:41`); object z limits `SL_MAX_OBJECT_Z 4096` vs `OS_MAX_OBJECT_Z 10000` / `OS_MIN_OBJECT_Z −10000` (`llmath/xform.h:38-46`). FS supports OpenSim **var-regions**: `LLWorld::mWidth` is mutable (`newview/llworld.cpp:89`, set from `region_size_x` in `addRegion :569-570`), region sizes are read from `EnableSimulator`/`TeleportFinish`/`CrossedRegion` extra fields under `#ifdef OPENSIM` (`llworld.cpp:1620-1637`, `llviewermessage.cpp:3700-3716`, `:4152-4168`), and the terrain/parcel code sizes itself from `getWidth()` (`newview/llviewerobject.cpp:1300`, `llviewerparceloverlay.cpp:71`). SL is always 256.
- Three coordinate frames: **global** (`LLVector3d`, metres from grid origin), **region-local** (`LLVector3`, 0..256), and **agent** (`LLVector3` relative to the agent's current region origin, `gAgent.getRegion()->getOriginAgent()`); objects store agent-frame positions, so a region change calls `gObjectList.shiftObjects(delta)` and `LLWorld::updateAgentOffset` (`llviewermessage.cpp:3927`, `llagent.cpp:1199-1210`), and the renderer uses `gShiftFrame`. Audio uses global F32 (§6).
- `LLWorld` (`newview/llworld.cpp`) keeps `mRegionList/mActiveRegionList/mVisibleRegionList/mCulledRegionList` (`:602-604`, `:1060-1114`); `addRegion` (`:520-675`) links each new region to the eight neighbours by handle (`connectNeighbor`, `:625-666`, which stitches `LLSurface` edges, `llviewerregion.cpp:2053`); `removeRegion` (`:677`); `resolveRegionGlobal` (`:917`); `updateRegions(max_time)` (`:1121`); land far clip controls which neighbours are kept (`setLandFarClip :1297`). The viewer holds **one circuit per connected region** (the agent region plus every `EnableSimulator`-announced neighbour within draw distance) and gets `ObjectUpdate*`, `LayerData`, `CoarseLocationUpdate`, `ParcelOverlay` from each; FS `FSDisableNeighbourRegionConnections` can refuse neighbours (`llworld.cpp:1598-1614`). The "child agent" concept is server-side only — the viewer never sends `ChildAgentUpdate`; it sends `AgentUpdate` to its current region and `AgentPause/AgentResume` to all (`:1744-1795`).

### 11.2 Teleports and region crossings
- `LLAgent::ETeleportState` (`newview/llagent.h:710-720`): `NONE, START, REQUESTED, MOVING, START_ARRIVAL, ARRIVING, LOCAL, PENDING`. Requests: `TeleportLocationRequest` (`llagent.cpp:5095-5120`, `:5387`), `TeleportLandmarkRequest` (`:5180`), `TeleportLureRequest` (`:5218`), `TeleportCancel` (`:5241`; FS can restore a cancelled request, `:5255-5260`). Progress: `TeleportStart {TeleportFlags}` (`process_teleport_start`, `llviewermessage.cpp:3456`), `TeleportProgress`, `TeleportLocal` (`:7869`, in-sim; no new circuit), `TeleportFailed`, and `TeleportFinish {AgentID, LocationID, SimIP, SimPort, RegionHandle, SeedCapability, SimAccess, TeleportFlags}` (`:3642-3760`): `enableCircuit(sim_host, true)`, `LLWorld::addRegion`, `setSeedCapability`, then `send_complete_agent_movement(sim_host)` and the arrival handshake repeats (§1.4). During `TELEPORT_ARRIVING` `idle()` only unpacks terrain and updates regions until the first objects arrive (`llappviewer.cpp:6119-6135`).
- Walking across a border: the sim sends `CrossedRegion {SimIP, SimPort, RegionHandle, SeedCapability, Position, LookAt}` (`process_crossed_region :4118-4180`) → `send_complete_agent_movement` to the new sim, `addRegion` (usually already connected as a neighbour), `setSeedCapability`; `AgentMovementComplete` then flips `gAgent.setRegion` and shifts the frame. Objects that straddle the border get a redundant region/position update in `processUpdateMessage` (`llviewerobject.cpp:1246-1253`); FS marks the avatar `setIsCrossingRegion` to avoid losing attachments (`:4139`). The old region stays connected as a neighbour; `DisableSimulator` eventually closes it.
- Caps and the event poll are per region; `LLEventPoll` stops when the region dies, and `EstablishAgentCommunication` on the **agent region's** event queue delivers neighbours' seed caps (§1.4).

### 11.3 Terrain, wind, water, parcels, estate
- Terrain: `LayerData` `'L'` patches decoded by `LLVLManager` (`newview/llvlmanager.cpp:105-145`) into `LLSurface` (`newview/llsurface.cpp`; grids per edge from region width, `:154-160`; `decompressDCTPatch :868`, 16×16 or large patches) → `LLSurfacePatch` → `LLVOSurfacePatch` drawables; composition from the four handshake textures and height ranges (`LLVLComposition`), PBR terrain (`RenderTerrainPBREnabled`, `llviewerregion.cpp:1714-1725`). Wind (`'7'`) feeds `LLWind` (sampled in `idle()` for audio and sky, `llappviewer.cpp:6235-6250`); clouds (`'8'`) are legacy; water (`'W'`) is height only (`WaterHeight` in the handshake, `waterHeightRegionInfo`, `llworld.cpp:1318`).
- Parcels: `ParcelOverlay` is a per-region 4 m-grid byte map (`PARCEL_GRID_STEP_METERS = 4`, `llinventory/llparcel.h:40`; bits `PARCEL_COLOR_MASK 0x07` with `PUBLIC/OWNED/GROUP/SELF/FOR_SALE/AUCTION`, `PARCEL_HIDDENAVS 0x10`, `PARCEL_SOUND_LOCAL 0x20`, `PARCEL_WEST_LINE 0x40`, `PARCEL_SOUTH_LINE 0x80`, `:71-84`) kept in `LLViewerParcelOverlay`; `ParcelPropertiesRequest` (`newview/llviewerparcelmgr.cpp:586`, by position/selection) → `ParcelProperties` (template at `../scripts/messages/message_template.msg`, `UDPDeprecated` → arrives on the event queue) with ~50 fields (flags, owner, media/music URLs, landing point, prim counts, access overrides, environment version) into `LLParcel` (`llinventory/llparcel.h`); edits via the `ParcelPropertiesUpdate` cap or message (`:1405-1431`). Parcel flags gate sound (§6.3), media, fly, build, scripts, push, etc.
- Estate/region info: `RegionInfo` (`LLViewerRegion::processRegionInfo`), estate covenant, `EstateAccess`/`EstateChangeInfo`/`DispatchRegionInfo` caps; god/estate-manager powers come from `GrantGodlikePowers` and the handshake `IsEstateManager`. `SimulatorFeatures` (cap) is an LLSD map (`setSimulatorFeatures :2616`) carrying `MeshRezEnabled`, `PhysicsShapeTypes`, `MaxAgentAttachments`, `VoiceServerType`, `map-server-url`, OpenSim extras (`OpenSimExtras`: export permission, `MaxMaterialsPerTransaction`, say/whisper/shout ranges, etc.).

### 11.4 OpenSim compatibility layer
- Grid selection is `LLGridManager` (`newview/llviewernetwork.h:73`, `grids.xml` in user settings or `app_settings`, `llviewernetwork.cpp:83-95`) with per-grid `login_uri`, `helper_uri`, `slurl_base`, login page (`:44-62`, `:547-589`); `isInSecondLife()/isInOpenSim()` (`:225`) are queried all over newview.
- `#if OPENSIM` appears at **265 sites in 85 newview files** (plus `llmessage`/`llcommon`). What it switches: login options (`lllogininstance.cpp:197-209`), var-region sizes, legacy UDP paths for textures (`ImageData/ImagePacket`, §4.2), assets (`TransferRequest`, §8.8), inventory (`FetchInventory*`, `UpdateInventoryItem`, §8.3), legacy client-side baking (`[Legacy Bake]`, §5.11), Vivox voice (§6.6), economy (`EconomyDataRequest`, currency), OpenSim search/destination URLs, `OpenSimPBRTerrain` cap, Hypergrid "My Suitcase" folder, higher object-z limits and 60 s audio uploads, the "4096 bug" long-jump fix on `AgentMovementComplete` (`llviewermessage.cpp:3921-3937`). `LLMessageSystem::setIsInSecondLife` (`llstartup.cpp:2061`) re-enables HTTP options that SL disallows. For the Rust design this means: transport selection must be a runtime capability negotiation per region (cap present → HTTP; else UDP legacy) rather than a compile-time switch, and the var-region/width assumption must be a per-region value from day one.

### 11.5 Other constraints worth noting
- Local ids are per-region and reused; identity is UUID + (region host). Objects can arrive before their parents (orphan handling) and children before `KillObject` of parents; attachments are regular objects parented to the avatar with the attachment point encoded in `State` (§5.5).
- The server decides visibility/interest (interest-list, `InterestList` cap) and chat range (§9.4); the viewer decides LOD, texture resolution, impostoring, and audio spatialisation.
- Messages are trusted-by-circuit: anything that arrives on a region's circuit is believed. Some messages are blacklisted from UDP and must come via the event queue (login `udp_blacklist`).
- Time dilation (`TimeDilation U16` in every object update) tells the viewer how slowly the sim is running; the viewer scales interpolation accordingly.
- The region handshake `CacheID` ties the on-disk VOCache to a sim incarnation; a sim restart changes it and invalidates the cache.
- Login, caps, mesh, textures and assets are all HTTPS to different hosts (login.cgi, sim cap server, asset CDN `asset-cdn.glb.agni.lindenlab.com` via `ViewerAsset`, appearance service); connection limits per policy class matter for CDN behaviour (§4.2).
- Firestorm's LSL bridge (`FSLSLBridge`) and NaCl antispam sit in the chat path before RLVa (`llviewermessage.cpp:3125-3134`), and FS keeps an "asset blacklist" that drops objects/sounds/animations by UUID at the message layer (`llviewerobjectlist.cpp:682-686`).

### 12.1 Data-flow contracts between crates
- `sl-messages` produces decoded, owned message structs on a channel; `sl-world`/`sl-comms`/`sl-avatar` subscribe by message type (a dispatch table generated from the template, not hand-registered per name). Event-queue bodies are decoded by the same generated code from LLSD.
- `sl-world` exposes immutable snapshots (or a change log) of objects/regions per frame; `vk-render` and `sl-audio` read snapshots, never the live store. Dirty flags become explicit `ObjectChange { id, kind }` events rather than bits on a drawable.
- `sl-inventory`, `sl-comms`, `sl-rlv` emit **domain events** (`OfferReceived`, `ScriptDialogRequested`, `RestrictionChanged`, ...) and accept **commands**; `sl-ui` is the only consumer that turns them into widgets. This is the inversion of Firestorm's `process_* → LLNotificationsUtil::add → XML-template-named callback → send reply` loop.
- `sl-rlv` is consulted through one trait object at the interception points listed in §7.9 (chat out/in, IM out/in, teleport request, attach/detach/wear, sit/stand, touch/edit/rez, camera limits, name rendering, map/minimap, inventory open, environment). All of those already exist as single functions in the crates above; none are rendering concerns except the vision-sphere effect, which is a render parameter.

### 13.1 Things the C++ gets right and the rewrite should keep
- The two-transport message bus (UDP template messages + event-queue LLSD routed to the same handlers) and the per-region circuit/caps/event-poll triple.
- Reliable-packet semantics (acks piggybacked, resend by averaged ping × 5, max 3 retries), the 5 s ping heartbeat / 100 s timeout.
- Visibility-driven object instantiation from the VOCache (objects are decoded only when their cached bounds enter the frustum) and CRC-based cache probes.
- Time-sliced work budgets everywhere (region update 1 ms, texture list fractions, object creation throttle) — translate to cooperative budgets in the frame scheduler.
- Dead-reckoning with phase-out (3 s / 2 s) and ping-based position advance.
- Progressive J2C by discard level with byte-range fetches and a global memory-pressure bias (§4.10); mesh header-then-LOD fetching with disk-cache preambles.
- AIS v3 + atomic COF slam + server-side bake keyed by COF version (§8.10).
- The RLVa command grammar and behaviour table (§7) — reimplement exactly, as scripts in the wild depend on its quirks.
- Mono 44.1 kHz world sounds, gain/d² priority, parcel sound-local gating (§6.9).
